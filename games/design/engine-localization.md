### 6.10 多语言文案

每个包、游戏和内核各有一个 `i18n/` 目录，每种语言一个 JSON 文件。内容、包的名称与简介，以及类型、形状、能力声明中的说明和 Studio 标签都用 `@键`。组装时，键加上所属命名空间。游戏或包可在 `overrides/<命名空间>/i18n/<lang>.json` 覆盖获准修改的内容文案。数字、逻辑符号、变量、端口 ID 等语言中立的值直接写在源文件里。

例如，声明文件写：

```json
{ "about": "@kind.part.fields.ports.about" }
```

操作集给作者写入的语言对象分配稳定的字段键。声明注释按声明目录、文件名和字段路径命名。修改文案、重排或移动沿用原键，复制成独立字段时分配新键并复制已有译文，删除字段时清理独占的键。Studio 和 CLI 共用这套操作。

JavaScript 以中文原文作为界面键。`tr('清空')` 读取当前语言，`T('清空')` 保留各语言供渲染时选择。包从 `kernel/words` 导入，两种运行环境都把这个公开入口绑定到调用包的语言目录。带变量的句子写 `tr('第 {n} 关', { n })`。语言可调整占位符的顺序。`en.json` 可以同时包含内容和界面文案：

```json
{
  "kind.part.fields.ports.about": "Ports this part exposes.",
  "ui": {
    "清空": "Clear",
    "第 {n} 关": "Level {n}"
  }
}
```

中文文件只存内容键。原文相同而英文因语境不同的界面用语，可用 `tr('输入', {}, 'capability-browser')` 指定语境，译文存入 `ui` 的 `输入 ⟦capability-browser⟧` 条目。缺译的界面键直接显示中文原文。

在 `site/` 运行 `npm run words -- --check`。内容、玩家界面和运行反馈要求覆盖所安装的语言，缺译会失败。开发者文案缺译时回退中文，检查单独计数。开发者文案包括 Studio、操作集、流水线中的界面用语，游戏内仅在 Studio 打开的编辑控件，明确采用 `studio-editor` 语境的包注册用语，以及 JSON 中的包简介、类型显示信息、`about` 和能力种类的 `studio.label`。完全相同且只含数字、符号或变量的条目也会报错。

在 Studio 的文案工作区，内容文本按字段分行，界面文案在「界面文案」范围内用同一个查询框和双语列。切换到包列表中的「内核」可编辑内核界面。内容用 `text.set` 编辑，界面用 `ui.set` 按原文键与语言修改，中文原文在代码中维护。变更可以一起预览、比较、应用和撤销。

发布时，`content.json` 引用独立的内容语言文件。界面目录随各自的代码载入，切换时界面和内容使用同一个语言代码。文案迁移不改变任务印记。基线对比将同值的语言中立目录引用和普通字符串视为同一显示值。
