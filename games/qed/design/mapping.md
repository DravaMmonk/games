## 1. 映射：把《图灵完备》搬到证明器上

《图灵完备》从 NAND 造出计算机，最后用自己的计算机写程序。这里从真值和两块核元件起步，造出证明器，最后用自己的证明器证定理。每一章给证明器装上一个模块，线上传的东西往往也换一次，这就是抽象在上升：

| 章 | 线上传的东西 | 元件是什么 |
|---|---|---|
| 真值电路 | 真值（是 / 否） | 连接词的门 |
| 证明核、连接词、量词规则 | 定理（「这句已经证出来了」） | 推理规则；证出的引理 |
| 简单的证明助手 | 证明状态 | 逆用规则、「引用已知」规则卡；汇合候选；框（重复、回溯搜索） |
| 量词的语言与反例 | 公式（玩家用块拼）；世界 | 拼公式板、反例板 |
| 规则与元变量 | 等式组；目标与规则（带 ?P） | 合一的规则；规则作用于假设、前向推理由逆用规则搭出，收尾时接入「引用已知」 |
| 策略 | 证明状态，可能有多个结果 | 目标后移、逐个目标和搭出的策略 |
| 经典逻辑 | 定理；证明状态 | 一条新的核规则反证法，和用它证出的引理、等价律 |
| 化简器 | 证明状态（要化成某个样子的句子和等式） | 改写一处；由它搭出的化简 |
| 归纳类型 | 证明状态 | 类型声明生成的构造子、递推子、归纳规则 |
| 自动化与证书 | 子句集，然后是重建的证明 | 子句形式、归结、饱和器、证书重建 |

| 《图灵完备》 / 已有几款 | 证明完毕 |
|---|---|
| 原件 NAND | 第 1 章是连接词的门（∧、¬ 起步），第 2 章起是证明核的两块元件（套用和假设框，Lean 内核的函数应用和 λ）；K、S 用框证出来当元件，专题拿掉框只用 K、S 和套用，那份费劲说明框为什么是基础元件 |
| 搭好的电路变成元件 | 证出的引理、组合出的策略、化简、证明重建器都变成元件。每一块都跑玩家通过那一关时的那块板（引理跑证出它的证明板），所以黑盒和"搭出它的那一关"一致：引理的陈述就是那一关的目标，`validate.js` 查引理单独接上那一关的已知就证出它；策略、化简用那一关的测试校验 |
| 测试 + 反例 | 证明关的目标就是规格，目标是假的时给反模型；策略和化简的测试是一组目标，逐个跑、逐步回放 |
| 机体 | 只有一台：玩家自己的证明器，每一章装上一个模块，装上的模块一直在证明器里。每种板一套托盘（`trays`：真值电路 `gates`、证明板 `proof`、机器板 `machine`；另有只用归结的 `resolution`，「别人的证明器」那一幕的 `certificate`），关卡或任务写它用哪一套。机器板上的规则元件不进托盘，由规则书给出：见过的核规则和证出的引理都在 |
| 用自己的 CPU 跑程序 | 策略一章，用自己组合出的 `auto` 重新解连接词一章的关 |

**要练出的思维：** 先写清规格再动手证；先找反例再找证明；分清语法和语义（⊢ 和 ⊨）；从结论倒推、把目标拆成子目标；证明是可以检查、可以计算、可以由程序产生的对象；引理与复用；加强归纳假设；知道自动化的边界在哪里，以及为什么它的结果仍然可信；分清检查过的和被相信的。
