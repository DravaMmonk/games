# 《证明完毕》设计框架：造一台证明器，学会写规格

公式连接词和量词是 `logic/symbol`（`packages/qed/symbols/`）。每个符号用 `at` 指定它首次可用的关卡，沿先修链开放给后续关卡。填句子条按 `logic` 的符号顺序提供可用键，题目与作用域补充变量、常量和谓词，`wordSets` 提供显示文字。证明板、机器板和真值电路各选自己的元件托盘；纯句子任务使用句子编辑器。翻译和查询通过 `sentence` 使用同一套拼搭界面，由 `logic` 提供公式规则和判定，符号解锁在通关窗口用符号标识。

所有玩法的任务板只显示简报和可展开的提示。翻译任务把操作要求写入简报（`brief`），把待翻译的原句单独写入 `say`；文案称拼公式用的项为「卡片」。多段关卡通过任务导航切换；元件工坊从关卡地图打开。

《证明完毕》（Q.E.D.，id `qed`）有两个互相支撑的目标。一是**证明器本身的机制**：Isabelle 和 Lean 这样的交互式证明器，里面到底是怎么运转的。学习者从真值和语法树起步，一层层亲手造出一台小小的通用证明器：可信的证明核、自然演绎、带元变量的规则消解、能回溯的策略、经典推理、化简器、自动化与证书，最后用数与列表练习定义与归纳。二是**人在形式化验证里不可替代的那部分工作**：把要求写成规格，检验规格和原意一致，分清哪些是检查过的、哪些是被相信的（第 0 节）。前者是后者的地基：不知道证明器怎样运转，就说不清它保证了什么、没保证什么。所有类图灵完备游戏共同遵守的结构、规则和自动检查见 [`games/design/README.md`](../../design/README.md)；本文档只记录这个专题自己的内容。改课程之前先改这份文档，过时的内容随改随删。

**主线：通过搭板练习形式化证明。** 关卡先围绕玩家能观察的问题展开：手头有哪些已知，目标能否拆开，还要证什么，哪条路走不下去。只有在玩家需要用它解释现象时才引入术语。Isabelle、Lean 和 Coq 的设计提供参考，游戏里的元件、表示和交互按学习问题来选。

**名字少提，百科详讲。** 关卡文字（引言、简报、提示、点题）只在引言里少量提一下软件的名字，说清「这里迁移了谁的思路」，一章至多一两处；软件本身的设计、历史和取舍写在百科（`glossary.json`）里，如「证明助手：Lean 与 Isabelle」「证明即程序」「世界与反模型」。

**课程对照（次要）：** COMP30026 Models of Computation（25S2）的逻辑部分（笔记 `docs/Unimelb/25S2/MoC/` 01–05 篇）和第 0–6 章大体重合，用作例题来源；计算理论部分只保留「为什么证明器不能全自动」这一条（第 11 章专题「机器做不到的事」）。

**现状：** 课程包含第 0–12 章。内容全是数据，按 `kit/domains/logic/vocabulary.js` 的词汇表写：`game.json`（课程的代际和几套词）、`parts.json`（原始件、引理、门和等式）、一关一个 `levels/<关卡 id>.json`（参考解和 naive 解是蓝图文本，声明的是规则表上的几行）、`glossary.json`；界面和规则在 `kit/domains/logic`。第 0 节的改版还没做完的部分记在第 7 节。

**终点：** 学完以后，学习者能做证明器替他做不了的那部分工作，也知道证明器替他做了哪部分：

- **翻译**：把一段话写成声明、定义和定理陈述；知道声明写不出什么，什么时候该用定义而不是声明；
- **检验**：拿具体情况和反例测一份规格，把两份长得很像的规格区分开，找出太弱（不该放过的也放过）或太强（该通过的不通过）的地方；
- **信任**：分清核检查过的、定义展开得掉的、公理和模型假设里被相信的；知道自动化找到的证明为什么仍然可信，证明器为什么不可能全自动。

撑起这三样的，是手里一台自己造的证明器，和对它每一层怎么来的理解：

- 证明核很小，定理只能由核规则产生，所以再聪明的自动化也造不出假定理（LCF）；一个证明也可以是一个项，核只检查它的类型（de Bruijn 准则）；
- 规则消解靠合一：带元变量 ?P 的规则和目标合一，目标换成规则的前提；合一的解可能不止一个，所以要回溯；
- 证明状态本身就是一条定理（Isabelle）或一组元变量（Lean），策略是产生证明的程序，组合起来就是 `auto`；
- 只用引入和消去规则的 auto 证不出排中律：经典推理要多一条反证法，它没有对应的程序；
- 化简是按方程定向改写，配上条件、合同规则和定义展开；
- 证明是程序：→ 引入是 λ，套用是函数应用，∧ 是有序对，∀ 是依赖函数，证明里的弯路算掉就是 β 归约；
- 归纳类型自动给出构造子、递推子和归纳原理，递归要证终止；
- 相等也是一个类型：改写就是给出一个「动机」；定义相等和命题相等不是一回事；
- 自动证明器找到的证明要变成核能检查的证书；而且证明器不可能全自动（一阶逻辑的有效性只是半可判定）。

看到 Isabelle 的 `thm`、`⋀`、`⟹`、`?P`、`rule`、`erule`、`back`、`THEN`、`simp add:`、`datatype`、`fun`、`induction`、`sledgehammer`、`metis`、Isar 的 `have … show`，Lean 的 `fun x => …`、`⟨a, b⟩`、`exact`、`apply`、`?m`、`rfl`、`▸`、`Eq.rec`、`induction … with`、`decide`，能说出它对应自己造的哪一块。
