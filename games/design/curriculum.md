## 2. 课程结构

**包提供对象，游戏编排课程。** 关卡设计在 `packages/<包>/` 里做：关卡、元件、词条各自独立，标签把同种对象收成集合，关系写先修和元件取代。标签没有教学含义，也不规定一关只能属于一个组；同一关可以出现在几个标签里。包之间可以依赖和覆盖，基础元件可以放进库包共用（第 6.1 节）。

**章是游戏层的内核对象。** 游戏配置 `game.json` 的 `chapters` 是 `list<chapter>`，给出章的全名和顺序。每章独立写在 `games/<游戏>/chapters/<章>.json`，全名为 `@<游戏>/<章>`。章的 `levels: list<level>` 保存具体关卡全名，`rows` 保存路线图。章文案和现有 `machine` 字段随章保存。原本用数字 id 编号的章增加 `number`，保留现有地图编号。游戏配置的 `encyclopedia: list<section>` 保留百科分组的显示顺序，分组内顺序取其 `values`。可选关和可跳过关由游戏分别加入内核的 `kernel/optional`、`kernel/skippable` 关卡标签。导入标签会一次性展开并写入章的列表，之后由游戏维护顺序。

```json
// games/qed/game.json
{ "chapters": ["@qed/paper"] }
// games/qed/chapters/paper.json
{
  "chapter": { "title": "@course.eras.paper.chapter.title" },
  "levels": ["qed/table", "qed/always", "qed/onerow"],
  "rows": [["qed/table"], ["qed/always", null, "qed/onerow"]]
}
```

**先修来自关系。** 包的 `relations/<名>.json` 声明 `requires`；一条边两端都在课程里才生效。游戏要改变它，就覆盖这份关系，不另写一套依赖图。普通前置要求通过；来源关可跳过时，普通边改等它的前置，带 `required: true` 的边仍要求通过来源关。跨游戏边写 `{ "from": "qed/table", "game": "qed", "to": "…" }`，读取来源游戏的通过记录。参考解所需能力也参与技术依赖检查。关内任务的 `optional` 和课程的可选关分开。

游戏只检查它选入的关；没选入的关和在那里打开的百科不进入这款游戏。托盘上的元件或阶段有没有关带来，只在完整选入相关包的游戏上判断。游戏用 `circuit/primitives` 标签选开局原始元件，用 `words` 选一套默认词表。`adds`、`local` 归关卡或任务，`replaces` 归包的关系。游戏可覆盖文案、先修边和标签成员。关卡机制、元件、阶段和托盘由包维护。

**包没有课程。** 它可以只有元件，也可以只有依赖别包的关卡。包检查逐关独立运行；单关试玩使用这一关的托盘和任务，没有章、解锁和进度。电路玩法不写托盘时提供全部元件。安装进度包时可以使用元件的完整阶段。内核的 `package-play.js` 提供临时单关运行壳，不生成可保存的包课程。

**存档按任务记。** `kit/shell/progress.js` 保存关卡通过记录和成绩，以及按任务全名保存的作品、存档槽、通过记录和发布作品。任务可以重排、移到另一关，记录仍跟着任务走；id 一经建立不能改。`kit/engine/stamp.js` 按任务数据和包提供的 `stamp` 计算戳，文案和版面不参与；谜题改变时清理对应任务，玩法定义变化按包的戳规则使任务失效。开发阶段不要求存档迁移。

### 2.1 机体与时代

机体描述学习者能操作的环境和外部能力，时代是课程分组；一门课也可以围绕同一机体逐章扩展能力。设计时说明能力的来历和变化，让玩家理解已有工具在新问题中的作用。

### 2.2 能力引入

引入关为后续问题建立必要的概念和能力。根据主题选择直接说明、示范、实验或构建；注意新模型、表示和操作之间的认知跨度。什么时候介绍工具、是否保存玩家实现，以课程目标和后续用途决定。

### 2.3 练习关

练习帮助玩家迁移和辨别，而非重复同一道题。可变化方向、复杂度、提示、组合和边界情况；同一关的多个任务或测试也能承担这些变化。不必为每个知识点或维度规定固定数量。

### 2.4 按问题组织关卡

围绕一个完整应用、延伸问题或机制原理设计一串关卡。按实际依赖接线，按教学需要安排关卡顺序。

### 2.5 延伸挑战

挑战可以在熟悉的能力上增加推理、组合或资源约束；依据目标提供反例、提示和足够有区分力的测试。当前引擎将挑战作为可选支线，具体审计见第 5 节。

资源约束写成任务的 `withholds`（第 2.8 节）：列出的元件（原始的或搭出的）这个任务不给，玩家已有也从托盘收起，写进板的文本时当作不认识的元件拒绝；参考解用到它，检查就报错。需要收窄设置时声明适当的元件阶段。约束要逼出一个想法，不只是逼玩家把收起的元件再搭一遍。例如同时收起差分和乘，让玩家发现翻倍数列的差分就是它自己晚一项。

### 2.6 关卡地图

地图把关卡画成按钮节点组成的树（`kit/shell/LevelMap.jsx` 的 `LevelTree`），规则是：
- 居中排列；几个关卡并排时整组居中。
- 地图按章内先修关系分层，同一层依课程顺序排列，每行最多三关。跨章先修通过锁关提示查看。
- 关卡统一用章号和章内数字序号，取自 `levels` 的顺序。关卡的内容 ID 用于编排板、引用和存档。
- 可选关用虚线描边，关卡分别显示「可选」和「可跳过」标签。里程碑用较大的按钮，包括每章第一关、首次引入元件、阶段或解锁作品的关。按钮右侧显示玩法图标，通关后可显示成绩。线路图的解锁标记显示电路元件。通关弹窗列出本次新获得的元件，以及在课程中刚满足全部前置的关卡。
- 游戏 `chapters/<章>.json` 的 `rows` 保存本章路线图布局，成员写关卡全名：每一行从左到右放哪些关卡，`null` 是空位，用来让关卡排得更整齐；一行最多三个位置，关卡要在它每个章内前置的下面。没有保存布局，或布局没写到的关卡，在满足已有布局的前提下按上面的规则排（`kit/course.js` 的 `mapRows`）：按先修关系一层一层排在前面各层的行之后，每行最多三关，排在它前置的下面、需要它的已排关卡的上面（插进的行把下面的行往下推）。
- 排得紧：一关只往下排到必须的位置（它的来路和同一列上面那关的下方，再避开横穿它这一列的连线拐弯），同一行的关不必对齐；连线上没有标签时，两关之间只留一小段线。
- 点一个还锁着的关，它和所有还要先通过的关一起高亮（跨章也算），并列出现在就能做的那几关，点一下直接去。
- 每关下面的连线上标出它带来的东西：这一关新带来的原始元件（这一关打开后显示名字，`introductions`），和通过它解锁的元件（通过后显示名字）。

先修边的挂靠位置也要考虑版面：一串支线挂在已经排满的位置，会被挤到下面，连线还会穿过别的关卡；这时换一个同样具备前置的挂靠关。

### 2.7 时代之间

时代之间可用新的问题、能力或情境说明学习方向；是否设置过渡任务取决于它是否有教学作用。

### 2.8 一关手里有什么

**托盘与进度。** `circuit/tray` 在 `trays/<名>.json` 声明元件、顺序和二级菜单。关卡或任务选一个 `tray`。`circuit` 默认直接提供托盘里的元件。启用 `progress` 时，托盘默认只显示其成员中已持有的元件。旧课程里还要显示已持有的未分组元件时，托盘声明 `includeUnlisted: true`，这些元件排在声明成员之后。参考解用到的元件和 `featuredParts` 进入主区，其余折进「更多」。

- `progress` 声明 `adds`、`local`、`gives`、`withholds`、`opens` 和 `awards`，从先修关系与任务通过记录推导可用元件。未安装该包时，使用这些字段、元件的 `stages` 或托盘的 `workshop` 会报错。
- `adds` 带来元件，`local` 将它留在引入处。`gives` 给当前任务加元件或阶段，`withholds` 收起元件或限制阶段。`opens` 在任务开始时开放阶段，`awards` 在任务通过后开放阶段。关卡的 `awards` 在整关通过时生效。
- 元件本身是第一阶段，`stages` 声明后续阶段，升级时保留原卡 id。托盘可以用阶段 id 选同一元件，并在单关试玩时选定设置。`replaces` 处理不同元件之间的取代。进度包检查托盘成员的引入来源与参考作品使用的元件和阶段。
- 封装元件可引用任务发布的 variant，运行实际通过的玩家作品，缺少玩家作品时运行参考作品。内核记录任务是否通过与玩法保存的作品，由包根据记录计算解锁。通过窗口由内核汇集新关卡、新百科词条和包各自报告的解锁项。

**公式符号。** `logic/symbol` 声明标记、文案、图标和可选 `at`。符号在指定关卡及经先修链到达的后续关卡可用，省略 `at` 时从开局可用。填句子条按 `logic` 的符号顺序显示，`logic` 检查参考句子使用的符号。符号在 Studio 单列，可直接编辑 `at`。《证明完毕》的八个符号在 `packages/qed/symbols/`，使用 `@symbol.<名>.…` 文案键。元件箱只列 `circuit/part`。
