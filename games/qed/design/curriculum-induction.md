### 第 12 章 · 数与列表

**动机：** 自动证明器在一堆句子里找矛盾，却多半不会归纳；化简器能把否定推进去，可「1 + 1 = 2」怎么证，数和列表从哪里来，0 为什么不等于 1，「对所有 x」怎么证，那台证明器回答不了。这一章把数和列表从头讲完，**数理规则书里的东西全由玩家声明出来**：类型在规则板上声明（第 3 章那块板：一条引入规则就是一个构造子），函数在定义板上定义，声明给出的规则（按情况分、归纳、互不相同）和定义的等式进数理规则书；一对一不是声明给的，用定义出的「前一个数」证出来。然后手算、把定义当改写规则交给化简、归纳先在证明板上手做再交给机器；最后一个专题从停机问题长到不完备性。

**数理规则书从哪里来（全部有出处）：**
- **类型**：声明自然数（nat = 0 | S nat）、声明列表（list = [] | x :: list）、声明真假（bool = 真 | 假），都在规则板上（`iso`，关卡写 `datatype: { type, ctors, args }`：第 k 条引入规则是第 k 个构造子，前提「自然数」「列表」的卡是那个类型的参数，任取一样东西是元素）。通过以后，类型进课程的类型表，之后的关写 `types: ['nat']`，不再自己写类型。证明核从声明生成规则，通关对话框列出来，通关文案讲为什么：
  - **按情况分**（exhaust）：第 3 章那条，一个构造子一种情况；
  - **归纳**（induct）：比按情况分多一步，S 要的参数正是自然数本身，拆开时能先对它用上要证的结论（归纳假设）；列表的 x :: xs 同理。生成器学会这一步是可选关的工作单，主线由证明核直接生成；
  - **互不相同**（distinct）：声明的一部分：只有这几条来路，来路不同造出的就不同（Lean 由递推子算出 `noConfusion`，要能返回命题的函数，这里不做，点题说明）。
  - **一对一**（inject）不再由声明给：先在定义板上定义「前一个数」pred（pred 0 = 0，pred (S x) = x），再在证明板上证 S x = S y → x = y（取 pred 两边，等量代换），证出的是一条规则（课程的 `facts`，规则形式 ⟦S ?x = S ?y⟧ ⟹ ?x = ?y）。
- **定义**：定义板（`define`）。一个函数一张板：按它要拆的那个参数，每个构造子一行左边（来自类型声明，所以每种情况正好一行：这就是按情况分）；带条件的定义（max）按条件的两种取值各一行。玩家给每行从几个候选里选右边。测试是几个要算出的值（用选的等式算，算不完 200 步就是「停不下来」），最后一行是「递归都在更小的参数上」（右边每一次调用自己，拆的那个参数都是这一行左边构造子里的变量）。通过以后，等式进课程的定义表，之后的关写 `defs: ['plus']`，按名字拿到等式（次序同定义板的行）。点题：每个构造子一行、递归只往小里走，这样的定义就是递推子的一次使用，一定停得下来（Lean 把它编译成 `Nat.rec`，Isabelle 的 `fun` 要证终止）。
  - 主线定义：加法 plus、前一个数 pred、拼接app、长度 len、比大小 le、较大的 max（带条件）、倒过来 rev、求和 sum 和累加求和 itsum；专题插入排序定义 if（按真假分两行）、ins、sort。
  - 例外（如实写进关卡）：停不下来的定义（`in-loop`）的 f(x) = S f(x) 是「假如收下这条定义」的已知，定义板正会拒收它；专题「真的，却证不出」的编码函数是关卡写出的等式（`stated`），讲的是编码，不是怎样定义，但写法同样每个构造子一行、递归在更小的参数上。
- **证出的等式**（课程的 `facts`：加零、加后继……）：不变。带条件的事实（`u = 真 → if u v w = v`）也是证出的，在重写书里是带条件的改写规则。

**原始元件只有归纳**（`natInd`，`kit/domains/logic/proof.js`）：证明板上一块两个框的元件，卡片上选要证的 ∀x. φ(x) 和第二个框里那个数的名字 a；第一个框证 φ(0)，第二个框假设 φ(a)、证 φ(S a)。它是数的归纳的证明板形式，所以先手做一遍，机器上的归纳规则才有前因。归纳不是一阶逻辑的推论，用到它的证明关不做反模型检查（`validate.js`）。

**关卡顺序**（先声明、再定义、再计算、再用声明给的规则；类型和函数都在第一次要用之前声明）：

| 路 / 段 | 关 |
|---|---|
| 数从哪里来 | 声明自然数（章首；规则板：0 什么都不要，S 要一个自然数；通关列出按情况分、归纳、互不相同，点明归纳假设从哪来）→ 定义加法（定义板：plus 0 y、plus (S x) y 两行；候选里有 plus x y 这种算错的、S (plus (S x) y) 这种停不下来的）→ 手算 1 + 1（证明板：两条定义是已知，三次选定一例、一次等量代换）→ 算一算（定义当改写规则，化简后自反）→ 在「对所有」底下 |
| 逐个目标 | 每个目标都做一遍（新框**逐个目标**：`ALLGOALS`、Lean 的 `<;>`；限 4 张卡片。放在这里，因为第一次非它不可是 0 加在右边：倒着用归纳规则得到 0 和后继两个目标，要做同样的化简） |
| 声明给出的规则 | 0 不等于 1（化简证不出，互不相同证得出）→ 一对一（两段：定义前一个数；证明板上取 pred、等量代换证出 S x = S y → x = y → **一对一**）→ 按情况分（exhaust 的 ?t 由后面的由假设得证定下来）→ 0 加在右边（三段：先算具体的数；证明板上用新元件**归纳**手证；再在机器上倒着用归纳规则 → **加零**） |
| 列表 ∥ 带条件的定义 | 声明列表（规则板：[] 什么都不要，x :: xs 任取一样东西再要一个列表）→ 定义拼接和长度（定义板两段：app、len）→ 列表也一样（化简）→ 拿已知改写 ∥ 声明真假（规则板：两条什么都不要的引入规则，`ways` 查出两条）→ 定义比大小和较大的（定义板两段：le 拆两层，max 按 le x y 是真是假各一行）→ 带条件的规则（max：依次尝试各走一条带条件的规则，条件证不出的那条自己失败） |
| 数 ∥ 列表 ∥ 为什么要停 | S 加在右边（→ **加后继**）、交换（→ **加法交换**）、结合（→ **加法结合**）∥ 接一个空列表（→ **接空列表**）、拼接也结合（→ **拼接结合**）、倒过来拼（两段：定义 rev；用前两条 → **倒过拼接**）∥ 不等于自己的后一个（x ≠ S x：归纳加互不相同和一对一 → **不等于后继**）、停不下来的定义（f(x) = S f(x) 推出矛盾：定义板不收它的原因） |
| 证明谜题 P（不在主线） | 长度相加、倒两次（用倒过拼接）、累加器求和（两段：定义 sum、itsum；itsum xs y = y + sum xs，∀y 留着，先加强命题） |

**工作单（可选专题 E）：生成器的测试给行为，不给规则。** 拆开它、每一条的测试改成「应当消去成什么」，判定拿生成的规则去跑这些情况（`elimgen.js` 的 `judgeElim`），不再显示要的那条规则。

**可选专题 · 归纳法是一句话**（`in-induct`，代号 X，接在声明自然数之后，还要先做过 X11 代换）：归纳规则写成一句已知 ∀P. P(0) → (∀n. P(n) → P(S n)) → (∀n. P(n))，沿用选定一例（选一种性质换掉 P）和套用。两个任务：用它（已知 0 + 0 = 0 和每一步，性质选 x + 0 = x，套用两次）；挑对性质（只有归纳法，证每个数要么是 0 要么是某个数的 S：性质就是目标里对 n 说的那句，0 的情况自反律加引入 ∨，S a 的情况 S a = S a 本身就是例子，用不着归纳假设）。关后点明：这句话就是声明的消去规则，0 加在右边的两个框的归纳元件做的是同一件事。

**可选专题 · 生成器遇上自然数**（`gen-nat`，接在声明自然数和前一个生成器关「生成器遇上任取」之后）：把自然数的声明交给消去规则生成器，它只给出按情况分，没有归纳假设；关后点明数学归纳法多出的就是对那个数先用上 ?R。

**工作单（可选关）：归纳假设由生成器生成。** 主线里声明自然数、列表的归纳规则由证明核从类型声明直接生成（`datatype.js`）。可选关：在生成器遇上自然数之后，在玩家此刻的生成器电路上升级（升级链的下一关），墙是原来的生成器只给出按情况分（⟦?n = 0 ⟹ ?R; ⋀x. ?n = S x ⟹ ?R⟧ 那样的情况，没有归纳假设），证不出 0 加在右边；升级后前提里出现被声明的类型时多产出一个归纳假设，motive 跟着被消去的那个数走。严格正性做成辨真伪：喂进 `(T → ⊥) → T`，生成的消去规则推出 ⊥。主线不依赖这次升级。

**专题：插入排序**（挂在接一个空列表和带条件的规则之后）：插进去（定义板三段：if 按真假分两行、ins、sort，再化简算例子）、排一排（化简就是运行程序）、如果就分情况（两段：从 if 的定义证出两条带条件的规则 u = 真 → if u v w = v、u = 假 → if u v w = w，→ **如果为真**、**如果为假**）、插一个长一格（bool 的按情况分加上两条带条件的 if 规则：条件对上 ?t = 真 时 ?t 就定下来 → **插入长一格**）、一个都不少（用插入长一格）。

**专题：真的，却证不出**（`after` 本章主线末尾和停机问题，六关，哥德尔的整个论证一步一关；前三步用本章的化简亲手算，后三步在证明板上证）：句子变成数（`gd-code`：符号各一个数，下雨 1、地湿 2、¬ 3、→ 4，→ 写在两边前面不用括号；⌜A⌝ 由定义算成一串数；关后点明一串数还能用质数指数并成一个数）、检查证明是一次计算（`gd-check`：证明是一棵树，叶子是公理、分叉是套用；「查」「结论」由定义算出，公理表三条；关后点明 Prov(⌜A⌝) 就是「有一个数是能通过检查、结论是 A 的证明」，检查总算得完，找证明却可能找不完）、对角线是一次计算（`gd-diag`：D = 「对角 □ 证不出」，对角就是把句子自己的编码填进空位；化简算出 G = 对角 D，再算出 G 里说到的那句正是 G：对角线引理，G 里写进去的是 D 的编码和取对角的指令，不是它自己的编码）、我证不出（`gd-true`：已知 G ↔ ¬Prov(对角 ⌜D⌝)、上一关算出的 对角 ⌜D⌝ = ⌜G⌝、可靠 Prov(⌜G⌝) → G；先用等量代换改写，再证出 G ∧ ¬Prov(⌜G⌝)）、只要不矛盾（`gd-con`：不用可靠；三句已知各有来历：对角线是计算，证明器自己也算得出，所以 Prov(⌜G⌝) → Prov(⌜G 证不出⌝)；检查是计算，证明器把那个证明查一遍，所以 Prov(⌜G⌝) → Prov(⌜⌜G⌝ 证得出⌝)；不矛盾，两者不同时证得出；证出 ¬Prov(⌜G⌝)，关后点明第一定理的条件和罗瑟）、证不了自己不矛盾（`gd-second`：第一定理在证明器里再做一遍；关后点明希尔伯特计划、加公理也没用、证明器为什么只把信任压到一个小核）。仍当已知的只有两件：Prov 怎样用加法和乘法写成算术的话（可表示性），以及证明器能对自己做这些计算（可证性条件）；点题里如实说明。说谎者说的是真假，G 说的是证不证得出，同一个形状这一次得到的不是矛盾，而是一句证不出的真话。百科分清完备性（所有世界里都真的都证得出）和不完备性（自然数这一个世界里有真的证不出）；「哥德尔编码」从句子变成数开放。

**规格：** 声明类型、定义函数都是写规格；定义板拒收停不下来的定义，是规格自己的检验。新的类型和函数声明好以后接进玩家的证明器。专题「真的，却证不出」是信任的边界。
