### 6.7 Studio 与作者工具

Studio 外壳管理构建、编排、文案三个工作区及共用的选择、预览、变更集、覆盖审计和日志。构建面向包声明，编排面向游戏，文案按字段归属写入包文案或游戏覆盖。工作区使用统一内容加载、对象身份与 schema。

包的视图通过注册表提供专用编辑器、预览和显示。通用编辑器按 schema 读取字段并生成操作。快速预览和实际检查读取同一待定变更集，应用前重新核对版本。试玩使用组装后的草稿与专用存档。

编排打开、草稿稳定或内容刷新后在后台自动审计课程，包括检查参考解用到的元件在先修路线中是否可用。后台审计通过 `auditLines` 返回课程诊断，草稿编辑和应用沿各自的预览与校验流程继续。

Studio 另有只面向人的规范提示（见 [5.2](rules-and-checks.md)）。它读磁盘上已写入的内容，在内容变化后和页面可见时每两分钟由独立的后台工作线程计算一次，不进入任何队列：编辑、预览、应用前检查和写入既不等它，也不被它等待，运行失败时保留上一次的结果。提示列在审计工作单的单独一档，可逐条了结或重新打开；了结记录按「规则、位置、当前措辞」存于本机 `site/node_modules/.cache/games-studio/advisories.json`，措辞一变即失效。筛选栏的眼睛按钮在本浏览器整体关闭这项后台检查。该工具只登记在 Studio 的 HTTP 桥上，不属于操作工具集。

本机源码编辑走单独的保存与包检查，核对文件版本、语法和导入边界。外部适配复用同一作者工具，命令入口见 [作者流程](author-workflow.md)。

Studio 启动时并行读取游戏与包目录、加载工作区模块。本地开发服务监听 `games/` 和 `packages/` 中 JSON 配置与 JSONL 日志的新增、修改和删除。直接保存配置或点击顶栏的重新加载按钮会刷新列表和预览，当前工作区会把待定变更重新预览在最新磁盘内容上。
