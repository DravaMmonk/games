### 6.7 Studio 外壳与包编辑器

Studio 是操作集上的编辑器，按作者的职责分成三个工作区（`kit/studio/Studio.jsx`）：

| 工作区 | 打开什么 | 改什么 |
|---|---|---|
| 构建 | 一个包 | 元件、关卡、词条、标签、关系、托盘、百科分组、对象类型及覆盖；文案只作参考 |
| 编排 | 一款游戏 | 选包、章的有序关卡列表、可选与可跳过、路线图 `rows`；依赖编辑写成包关系的覆盖 |
| 文案 | 一个包或一款游戏 | 本层各语言、术语与引用，以及允许的文案覆盖 |

**三个栏各有一件事。** 顶栏切工作区，并放撤销重做、全局命令、语言与主题，再写出打开的包或游戏的名字，点它打开左栏对应的列表；顶栏两端的按钮收起或打开左栏和右栏（Alt+[、Alt+\），三个工作区都有。打开哪个包、哪款游戏都在左栏选：构建的第一个列表是所有包，编排的第一个是所有游戏（其后是这款游戏用到的包），文案有游戏和包两个列表（`ProjectLists.jsx`）。包列表、游戏选包、依赖列表和包标题都以当前语言显示包名，id 用小字，简介可悬停查看，也显示在包的元信息中。每个列表都能搜索（id、名字、用到的包），打开的那个标出；点一个，中栏显示它的元信息，右栏只放它的文件（包的 `package.json` 只读，没有改它的操作；打开着的游戏的 `game.json` 在右栏编辑，别的游戏只读）。元信息是（包：`package.json` 的版本、内核和依赖，被哪些包、哪些游戏用到，依赖锁定，代码导出，公开内容按类型计数；游戏：名字、主包、内核、选用的包、依赖锁定；只读）；双击、回车或右栏的「打开」换成它，有待定操作时先确认。构建的包列表可以新建包（空白，或复制所选的包；`create_package`），编排的游戏列表可以在所选游戏的包上新建游戏（`create_game`），建好后打开。构建左栏其后按内核类型和所有已加载包声明的类型列对象，默认集合由 `kernel/studio-left` 决定，另有能力和覆盖；编排列包、章、覆盖；文案按对象或文件列文字。组可折叠，一个对象可出现多次；点组名编辑组对象，搜索放在资源种类之后。来源和覆盖链始终可查，依赖包的对象只读，要改先「在本包覆盖」。

**左栏的列表一个样子。** 每个列表（包、游戏、关卡、各类对象、能力、覆盖、章节、文案的对象和文件、搜索）顶上是同一行工具（`SidebarListTools.jsx`），切换列表时位置和样子都不变：「＋」新建或复制，一个菜单按类别分节：先是这个列表的对象（如「关卡」下「新建关卡」「复制所选关卡」），再是这个列表能按它分组的每一类（「标签」下「新建标签」「复制所选标签」，「托盘」「关系」「分组」同样；关系按种类各有一项，如「新建先修关系」）；复制没有可复制的就变灰。新建或复制一个分组后，列表随即按那一类分组显示。复制出的对象文案不带原来的文案键，由操作另起、搜索框、视图菜单（分组方式、排序、筛选，以及搜索的匹配方式和范围、替换，都在这里，当前选中的打勾）、全部展开/收起。列表用不上的按钮变灰，不拿掉。列表里的每一项也一个样子（`ListRow.jsx`，关卡树自己画同样的部分）：图标、名字、需要时的标记，最右端右对齐、灰色的 id；位置不够时 id 先让，名字最后才截短；选中的一项样子相同。包和能力列表按类型或来源展示整张列表，各组可折叠。包的来源区分工作区和发布归档。包和游戏只列出已声明或有覆盖贡献的标签。新建的空标签可以立即编辑。能力行左侧是去掉来源前缀的短名，右侧是完整 ID，说明见中栏。

中栏放复杂、跨对象、需要直接看见的编辑：关卡单关试玩、元件的板、阶段链、标签、托盘、百科分组、关系板、章的接线板和路线图、能力说明、覆盖差异、语言对照。右栏随选择显示 schema 控件或原始 JSON，id 只显示。左栏按职责找资源，中栏按对象工作，右栏补任意字段，不再靠旧的「画面、字段、文案、比较、变更」顶栏页签分流程。

**关系和路线图分开。** 包关系板编辑 `requires`、`replaces` 的 `edges`，编排板增删先修边写成游戏覆盖。章内编号顺序编辑 `registries.chapter` 中对应对象的 `levels`，路线图编辑 `rows`，章序编辑游戏配置的 `chapters`。集合来源来自 `sources` 的 `collections`。列表排序、集合勾选与关系板使用同一套字段和操作协议。

**接线板照电路接线。** 关系板和章的接线板共用 `kit/studio/ArrangementBoard.jsx`：卡片的输入在顶边正中，输出在底边正中，这个排法不变；接线的手感照电路画布（`packages/circuit/view/board/CanvasEditor.jsx`）。点一个圆点拿起一根线，输入、输出都可以先点；再点另一种圆点或整张卡接上，点同一个圆点或板上空处放下。拿着线时能接的圆点闪动，不能接的（接到自己、已有、成环）不闪，草稿线是跟着指针的虚线。也可以从输出拖到输入或卡上松开，松在别处不接。拒绝的原因在板顶停留几秒。线有底色描边，悬停和选中加粗，选中的线带强调色光晕；圆点接上线后实心，没接线的输入里有小圈（`--port-mark`）。线的正中（选中或悬停时）和卡的右上角（选中或悬停时，只在能拿掉卡的板上）各有一个小删除钮；选中的线或卡按 Delete 或 Backspace 立即拆掉，不弹确认；Escape 先放下手里的线，再取消选中。卡片上写 id 和名字、只写 id 或只写名字（板右上角切换，各人记住），写在一行，卡片按字的宽度撑开，不省略。板上方显示所选对象的那一行高度固定，选中或取消选中时板不移动；拆线、拿掉卡只在板上做，这一行只放名字和设置（关系板的「须通过」，章的「可选」「可跳过」）。内核不能读包的样式，这套外观在 `studio.css` 里按 `wires.css` 和 `circuit.css` 的数值对齐。

**关系板改了就记下。** 接线、拆线、改「须通过」、拿掉卡，每一次都立即成为待定变更集里的一个操作，没有单独的保存；板不等预览，先按自己刚写的操作显示（`pending-view.js` 的 `pendingValue`：自己最后一次写入还在变更集里时用它；撤销后预览还没回来时用撤销前的样子；关系在别处又被改过时用预览的）。撤销、重做逐个操作进行。

**章板分三个页签。** 「顺序」是这一章的关卡，按玩的顺序排成带序号的一列（序号、名字、右端的 id），拖动或 Alt+↑/↓ 调整、× 移出，放到先修前面的移动被拒绝；列表上方的选择器把关卡或关卡标签放进这一章。点一关，列表下方列出它的文字（文案表只看这一关的文件），改动写成这款游戏自己的写法（`text.override`：游戏对关卡只能覆盖文字），清空一格回到包里的写法。编排的章节列表只列章，游戏自己的 `game.json` 从游戏列表打开。「依赖」是接线板；「路线图」左边编辑 `rows`，右边是玩家看到的这一章（`MapPreview.jsx`：在 `studio.html?play` 里用 shell 自己的 `MapChapter` 画，所有关卡打开，可切换桌面和手机的画法）。往章里放关卡的选择器在页签上方，三个页签都能用。顺序和路线图也像关系板一样改了就成为操作、不等预览先显示、逐个撤销。预览页把内容做成游戏要一秒以上，而且和 Studio 共用一条线程，所以只在内容除这一章的 `rows` 以外有变化时才重做；移动只把新的 `rows` 发过去重画（几毫秒）。

**编排里能试玩。** 编排工作区顶栏的「试玩」把中栏换成这款游戏本身（`GameFrame.jsx`，只玩不编辑：没有编辑模式），从地图开始，按玩家看到的样子玩：章、解锁、关卡都是游戏自己的，内容是待定变更集改过的样子，编排时改了什么，回来就看到什么。章板「顺序」页每一关旁的 ▶、或 ⌘/Ctrl+Enter，从选中的那一关开始玩（没选关时从地图开始）。试玩栏有「地图」回到地图、「回到编排」换回章板；试玩窗口打开过就一直留着，换回来时游戏还在原来的地方。试玩的存档是 Studio 自己的（`studio.<游戏>`），不碰玩家的。


**专用编辑器由包提供。** `view/register` 的 `editor` 按对象类型提供资源分组、编辑器与独立预览，玩法的视图登记提供关卡预览和编辑模式。元件与托盘编辑器归 `circuit/view`。电路元件阶段链由 `circuit/view` 注册，工坊开关由 `workshop/view` 注册，符号编辑器归 `logic/view`。内核维护工作区、三栏和辅助抽屉、内核对象编辑、schema/JSON 编辑、文案、章、路线图、覆盖审计和日志。缺少专用编辑器的类型显示字段，由右栏编辑。空内容工作区显示空状态；包工作区可以独立于游戏打开。

**修改只有一份待定变更集。** 画面、配置、检查、文案和 diff 都读 `preview` 的同一份结果；应用调用 `modify`，撤销已应用的修改调用日志 `undo`。三个工作区的顶栏都有撤销、重做：撤销去掉最后一个待定操作，重做放回来（⌘/Ctrl-Z，⇧⌘/Ctrl-Z 或 Ctrl-Y，在文字框外）。画面上的内容字段可点进右栏，包画面使用单关试玩，不借任何游戏的课程。审计、变更集和日志放在中栏的辅助抽屉。每次请求只要自己用得上的部分（`preview` 的 `omit`）：快预览不带文件全文、变更日志和漂移，整体检查只带检查结果，文件 diff 和日志只在变更页签打开、编辑停下后单独取。桌面可调栏宽，窄屏按工作区现有响应式呈现；样式和交互由 Studio 共用组件维护。

`npm run studio` 在 `http://127.0.0.1:5274/studio.html` 打开 Studio。端口被占用时启动失败。`kit/app/studio.js` 只把 `engine/ops/tools.js` 的工具映射到 HTTP，不另写内容逻辑；快预览和慢检查分开调度，写入等待检查并核对并发状态。`GAMES_ROOT` 指向含 `games/` 与 `packages/` 的副本，供试改。任何 agent 也需要的能力先做成共用工具，再接界面。

**能力与字段选项。** 能力浏览器使用种类声明的双语名称和顺序。字段选择器从 schema 的 `ref.kind` 读取对应的能力项。以能力项选择分支的形状，添加时用该项的说明帮助选择，已有对象仍保留原分支。

**包源码。** 本机 Studio 的「构建 → 源码」可以浏览、新建和编辑工作区包 `core/`、`view/`、`test/` 里的 JS、JSX 和 MJS 文件。能力详情的「在源码中查找」打开所属包，优先列出匹配能力名称的文件。「保存源码」检查语法和包导入边界，核对文件版本后原子写入。重新进入构建后读取已保存的实现。源码页独立于包插件加载，包代码加载失败时仍可进入源码页修复。「检查包」检查已保存的内容与实现，并在新进程中运行包测试。源码修改随 Git 提交，内容编辑仍走待定变更集。源码工具只在本机回环地址提供。
