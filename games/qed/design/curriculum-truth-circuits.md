### 第 1 章 · 真值电路（语义）　已做

**模块：** 证明器的第一块：一块门电路算出一句话在一行上的真值，机器把它在真值表的每一行各跑一遍（像《状态之图》的机器人逐格扫表）。原始元件是「非」「与」两个门，写在 `parts.json`；「或」「若…则…」由玩家拼出，拼出即解锁：拼出的门跑玩家通过那一关时的那块电路（`gates.js` 的 `builtGates`；没通过就开着的、或通过后又改得不再对的，用参考解），`validate.js` 查这块门单独接上字母就能通过那一关。拼出的门能打开看里面（只读，元件上是选中的那一行的值）：桌面上门的右上角有「编辑」和展开，手机上点开门，单子里是它的电路；元件箱里也画出它跑的那块电路。关卡种类 `gates`（`kit/domains/logic/gates.js`），屏是内核的电路屏（`kit/shell/CircuitScreen.jsx`，领域只交 `ui/gates.js` 一份声明：真值表的每一行是一条检验，在表里选行，逐行运行，门数上限是最后一条检验）。

**地基**

| 节 | 关 |
|---|---|
| 门 | 不是不下雨（两个「非」）、下雨但没刮风（「与」）、「非」管到哪里（同样两个门，接的先后一换就是另一句话：语法树决定意思；naive 解是另一种接法） |
| 造门 | 下雨或者刮风（只用「与」「非」）→ **或**、如果下雨那么地湿（用上「或」）→ **若…则…** |

**练习 · 三种句子：** 怎样都对，怎样都错（一关两个任务：永真式、矛盾式；输出那一列说明一切）、两个方向都对 → **等价 ↔**（门，专题里每一句「某人说」都用它）。真值电路模板默认显示目标真值。这几关通过 `hideTarget` 将模板的目标列设为隐藏，避免表格直接透出「全真」「全假」。

**专题：把谜题接成电路**（MoC 01：把问题编码成公式，再看哪一行满足）。这几关通过 `blind` 隐藏目标列和公式，只用话说出句子。专题练的是把自然语言翻译成逻辑语言，每关多一种说法的译法，过关点题写出完整的译文，等价的译法都算对；真的那一行就是答案。

| 关 | 加回的机制 |
|---|---|
| R1 翻译成与或非 | 把一句话（「a 和 b 不都是骑士」）翻译成与、或、非：「不都是」和「都不是」的区别（naive 解是后者） |
| R2 a 说的话 | 新译法：「a 说 X」=「a 是骑士」与 X 等价（用「等价」门）；naive 解只译一个方向 |
| R3 一个人说话 | 新译法：「a 是无赖」= 非（a 是骑士） |
| R4 两个人说话 | 新译法：几个人的话都对得上 = 各句的翻译用「与」接起来；「我们俩都是骑士」= a 与 b |
| R5 三个人说话 | 「都是无赖」正是 R1 的陷阱「都不是」；八行；人数每多一个，行数翻一倍（为归结一章埋下动机） |
| R6 至少与最多（终极） | 计数的话改写成「或」：「至少一个无赖」= 三人各自不是骑士的「或」；「最多一个无赖」= 每两人里至少一个骑士，三个「或」用「与」连起来；「a 不是唯一的骑士」= ¬a ∨ b ∨ c。唯一解是 a 骑士、b c 无赖（c 的话恰好为假）；点题联到排班这类问题交给 SAT 求解器时的写法 |

**挑战：** 只有一样（「要么下雨要么刮风，但不会两样都有」，最多 4 个门；逐行拼成要 5 个）。

**不单独做的：** 语法树板（「非」管到哪里已经讲清语法树决定意思）；求值器元件（反模型面板用引擎自己的求值）。

**规格：** 专题「把谜题接成电路」是第一次翻译：把一段话写成公式，每关的 naive 解都是一种常见误译（「不都是」译成「都不是」，「a 说 X」只译一个方向）。真值表的每一行就是一个情况，这是之后一切检验的原型。
